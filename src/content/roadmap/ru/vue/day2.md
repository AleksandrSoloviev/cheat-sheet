    title: "Что такое composable?"
    body: "#### Короткий ответ\n\nComposable — функция `useXxx()`, которая инкапсулирует **stateful**-логику на Composition API (`ref`, `computed`, `watch`, lifecycle). Прямой аналог **custom hook** в React. Это основной способ переиспользовать логику во Vue 3 вместо mixins.\n    \n#### Пример кода\n\n```\n// шпаргалка (не полный SFC)\n// composable\nexport function useToggle(initial = false) {\n  const on = ref(initial)\n  const toggle = () => { on.value = !on.value }\n  return { on, toggle }\n}\n```\n\n    \n#### Фраза на автомате\n\nComposable — это custom hook Vue: `useXxx` с refs/watch/lifecycle, вызывается в setup, с cleanup и желательно `MaybeRefOrGetter` на входе.\n    \n#### Мост с React\n``````````````\n\n| Vue | React |\n| --- | --- |\n| useXxx() composable | useXxx() custom hook |\n| внутри ref/watch/onMounted | внутри useState/useEffect |\n| mixins → composables | HOCs/classes → hooks |\n\n    \n\nПолный ответ: конспект Vue → Q31\n"

    title: "Как типичный composable выглядит «по-взрослому»?"
    body: "#### Короткий ответ\n\n«Взрослый» composable: принимает реактивный/статический вход (`MaybeRefOrGetter`), внутри трекает через `toValue`/`watchEffect`, делает cleanup, возвращает refs/методы — не сырые мутабельные объекты без нужды.\n    \n#### Пример кода\n\n```\n<script setup lang=\"ts\">\nexport const useUser = (id: MaybeRefOrGetter<string>) => {\n  const user = ref<User | null>(null)\n  const error = ref<unknown>(null)\n  const loading = ref(false)\n\n  watch(() => toValue(id), async (newId, _old, onCleanup) => {\n    const ctrl = new AbortController()\n    onCleanup(() => ctrl.abort())\n    loading.value = true\n    try {\n      user.value = await fetchUser(newId, ctrl.signal)\n    } catch (e) {\n      if (!ctrl.signal.aborted) error.value = e\n    } finally {\n      loading.value = false\n    }\n  }, { immediate: true })\n\n  return { user, error, loading }\n}\n</script>\n```\n\n    \n#### Фраза на автомате\n\nВзрослый composable: `MaybeRefOrGetter` + `toValue`, cleanup, возврат refs; async — abort в `onCleanup` у watch.\n    \n#### Мост с React\n\nСтруктура 1-в-1 с хуком:\n\n```\nfunction useMouse() {\n  const [x, setX] = useState(0)\n  useEffect(() => {\n    const onMove = (e) => setX(e.pageX)\n    window.addEventListener('mousemove', onMove)\n    return () => window.removeEventListener('mousemove', onMove)\n  }, [])\n  return { x }\n}\n```\n\n`MaybeRefOrGetter` ≈ «принять value или зависимость», близко к тому, что в React часто делают через `value` + отдельный `useEffect` на смену.\n    \n\nПолный ответ: конспект Vue → Q32\n"

    title: "Composable vs Pinia vs provide/inject?"
    body: "#### Короткий ответ\n\nТри разных масштаба шаринга: **composable** — переиспользуемая логика (часто локальный state на вызов); **Pinia** — глобальный доменный store; **provide/inject** — контракт внутри ветки дерева (как Context), без глобальности.\n    \n#### Пример кода\n\n```\n// шпаргалка (не полный SFC)\n// composable — логика на вызов\nconst { x, y } = useMouse()\n\n// Pinia — глобальный домен\nconst cart = useCartStore()\n\n// provide/inject — контракт ветки дерева\nprovide(formKey, formApi)\nconst formApi = inject(formKey)\n```\n\n    \n#### Фраза на автомате\n\nComposable = логика на вызов; Pinia = глобальный домен; provide/inject = Context ветки. Не мешать слои без причины.\n    \n#### Мост с React\n\n| Vue | React |\n| --- | --- |\n| composable | custom hook |\n| Pinia | Zustand / Redux Toolkit |\n| provide/inject | Context.Provider / useContext |\n\nПравило то же: Context ≠ глобальный стор всего приложения.\n    \n\nПолный ответ: конспект Vue → Q33\n"

    title: "Что такое Pinia? Чем лучше Vuex?"
    body: "#### Короткий ответ\n\nPinia — **официальный** store для Vue 3. Проще Vuex: нет mutations, отличный TypeScript, setup-stores как composables, модульность без вложенных modules-ада. Vuex знать полезно для легаси, писать новое — Pinia.\n    \n#### Пример кода\n\n```\n<script setup lang=\"ts\">\nimport { defineStore } from 'pinia'\nimport { ref, computed } from 'vue'\n\nexport const useCounterStore = defineStore('counter', () => {\n  const count = ref(0)\n  const double = computed(() => count.value * 2)\n  const increment = () => { count.value++ }\n  return { count, double, increment }\n})\n// vs Vuex: нет mutations, actions сразу меняют state\n</script>\n```\n\n    \n#### Фраза на автомате\n\nPinia — официальный Vue 3 store без mutations, с отличным TS и setup-stores; Vuex — легаси.\n    \n#### Мост с React\n\nБлиже всего к **Zustand** (простой API) + роль **Redux Toolkit** (официальный/стандарт команды). Mutations Vuex ≈ избыточный слой вроде классического Redux до RTK.\n    \n\nПолный ответ: конспект Vue → Q34\n"

    title: "Setup store — пример"
    body: "#### Короткий ответ\n\nSetup store выглядит как composable внутри `defineStore`: `ref`/`computed` + функции-actions, `return` публичного API. В компоненте state достают через `storeToRefs`, actions — напрямую.\n    \n#### Пример кода\n\n```\n<script setup lang=\"ts\">\nexport const useCartStore = defineStore('cart', () => {\n  const items = ref<Item[]>([])\n  const total = computed(() =>\n    items.value.reduce((s, i) => s + i.price, 0)\n  )\n\n  function add(item: Item) {\n    items.value.push(item)\n  }\n\n  function clear() {\n    items.value = []\n  }\n\n  return { items, total, add, clear }\n})\n</script>\n```\n\n    \n#### Фраза на автомате\n\nSetup Pinia = composable в `defineStore`: вернуть refs/computed/actions; в UI — `storeToRefs` для state.\n    \n#### Мост с React\n\nПохоже на Zustand:\n\n```\nconst useCart = create((set, get) => ({\n  items: [],\n  add: (item) => set({ items: [...get().items, item] }),\n}))\n```\n\nРазница: Pinia мутации массива (`push`) нормальны из-за реактивности Vue.\n    \n\nПолный ответ: конспект Vue → Q35\n"

    title: "Почему нельзя просто деструктурить store?"
    body: "#### Короткий ответ\n\n`const { count } = store` отрывает поле от реактивного store → дальше это обычное число/значение, UI не обновится. Для state/getters нужен `storeToRefs(store)`. Actions деструктурить можно — это функции.\n    \n#### Пример кода\n\n```\n<script setup lang=\"ts\">\nconst store = useCounterStore()\n\n// плохо — потеря реактивности\nconst { count } = store\ncount // больше не связан со store\n\n// хорошо\nconst { count } = storeToRefs(store)\ncount.value // реактивный ref\n\n// actions — ок\nconst { increment } = store\nincrement()\n</script>\n```\n\n    \n#### Фраза на автомате\n\nState/getters из Pinia — только через `storeToRefs` или `store.field`; actions можно деструктурить спокойно.\n    \n#### Мост с React\n\nВ Zustand `const count = useStore(s => s.count)` — подписка через селектор. В Redux — `useSelector`. Во Vue «просто деструктур объекта store» ≠ селектор, отсюда ловушка.\n    \n\nПолный ответ: конспект Vue → Q36\n"

    body: "#### Короткий ответ\n\nGuards — хуки навигации: глобальные (`beforeEach`), на route (`beforeEnter`), в компоненте (`onBeforeRouteLeave` и т.д.). Типичный кейс — auth: если `meta.requiresAuth` и нет сессии → redirect на login.\n    \n#### Пример кода\n\n```\n<script setup lang=\"ts\">\nrouter.beforeEach((to) => {\n  if (to.meta.requiresAuth && !isLoggedIn()) {\n    return { name: 'login', query: { redirect: to.fullPath } }\n  }\n})\n</script>\n```\n\n    \n#### Фраза на автомате\n\nGuards: beforeEach + meta.requiresAuth → redirect; для ухода со страницы — onBeforeRouteLeave.\n    \n#### Мост с React\n\nАналоги: RR loaders/actions, Next middleware, ручной redirect в `useEffect`. Идея та же — централизовать auth check, не размазывать по страницам.\n    \n\nПолный ответ: конспект Vue → Q39\n"

    title: "Слоты: default, named, scoped?"
    body: "#### Короткий ответ\n\n**Default** — `<slot />` / содержимое без имени. **Named** — `<slot name=\"header\" />` + `#header` у родителя. **Scoped** — слот с пропсами `:item=\"row\"`, родитель деструктурирует `#item=\"{ item }\"`. Scoped slot ≈ render props в React.\n    \n#### Пример кода\n\n```\n<template>\n  <header>\n    <slot name=\"header\" />\n  </header>\n  <main>\n    <slot>Default fallback text</slot>\n  </main>\n  <ul>\n    <li v-for=\"row in rows\" :key=\"row.id\">\n      <slot name=\"item\" :item=\"row\" :index=\"row.id\">\n        {{ row.name }}\n      </slot>\n    </li>\n  </ul>\n</template>\n```\n\n    \n#### Фраза на автомате\n\nDefault/named — куда вставить разметку родителя; scoped — ребёнок отдаёт данные в слот, родитель рисует UI. Это render props по-вьюшному.\n    \n#### Мост с React\n``````````\n\n| Vue | React |\n| --- | --- |\n| default slot | children |\n| named slot | header={...} / <HeaderSlot /> prop |\n| scoped slot | render prop renderItem={(item) => ...} или children(item) |\n\n```\n<List renderItem={(item) => <strong>{item.name}</strong>} />\n```\n\n    \n\nПолный ответ: конспект Vue → Q25\n"

    title: "Fetch в `onMounted` vs `watch`?"
    body: "#### Короткий ответ\n\nДанные от `route.params` / props — **`watch` с `immediate: true`** (или `watchEffect`), чтобы реагировать на смену id **без** remount. Один раз при открытии экрана без реактивной зависимости — `onMounted`. В Nuxt — `useAsyncData` / `useFetch` (SSR + ключ кэша).\n    \n#### Пример кода\n\n```\n<script setup lang=\"ts\">\nconst route = useRoute()\nconst user = ref<User | null>(null)\nconst error = ref<Error | null>(null)\n\nwatch(\n  () => route.params.id,\n  async (id, _prev, onCleanup) => {\n    const ac = new AbortController()\n    onCleanup(() => ac.abort()) // отмена при новом id / unmount\n\n    try {\n      user.value = await fetchUser(String(id), ac.signal)\n      error.value = null\n    } catch (e) {\n      if ((e as Error).name === 'AbortError') return\n      error.value = e as Error\n    }\n  },\n  { immediate: true },\n)\n</script>\n```\n\n    \n#### Фраза на автомате\n\nFetch от `id`/route — `watch` с `immediate: true` и abort в `onCleanup`; чистый one-shot без зависимости — `onMounted`. В React оба случая — один `useEffect([id])`.\n    \n#### Мост с React\n\n```\nuseEffect(() => {\n  let cancelled = false\n  fetchUser(id).then(...)\n  return () => { cancelled = true }\n}, [id])\n```\n\nОдин `useEffect` с `[id]` закрывает и mount, и смену id. Во Vue это явно раскладывается на «только mount» vs `watch`+`immediate` — частый собеседовательный нюанс про reuse компонента роутером.\n    \n\nПолный ответ: конспект Vue → Q30\n"
