### Q61. В чём главная философская разница?

**Короткий ответ на собесесе:**  
Vue: реактивные данные + templates (компилятор оптимизирует), «официальные батарейки». React: UI = f(state), иммутабельный rerender-мир, JSX и огромная экосистема. Оба компонентны; composables ≈ hooks.

---

#### Подробно

Vue делает ставку на:
- автоматический track зависимостей;
- SFC как единицу UI+стилей;
- прогрессивность (можно кусок страницы).

React делает ставку на:
- явный поток рендера;
- гибкость «собери сам»;
- одну модель для Web/RN/RSC.

На собесесе избегай «X лучше». Говори про trade-offs и билингвальность.

---

#### React — для якоря в голове

Ты 7 лет в React — это сила: можешь сравнивать осознанно, а не религиозно.

---

#### Фраза «на автомате» (1–2 предложения)

> Vue = reactivity + templates + batteries; React = UI=f(state) + JSX + экосистема; оба с hooks-подобным переиспользованием.

---

### Q62. Таблица «Vue ↔ React»

**Короткий ответ на собесесе:**  
На собесесе держи в голове таблицу соответствий — это быстро показывает, что ты не учишь Vue «с нуля», а переносишь модель.

---

#### Подробно

| Vue | React |
|-----|--------|
| `ref` / `reactive` | `useState` / `useReducer` |
| `computed` | `useMemo` |
| `watch` / `watchEffect` | `useEffect` |
| composable `useX` | custom hook `useX` |
| props + `emit` | props + callbacks |
| `v-model` | `value` + `onChange` |
| slots / scoped slots | children / render props |
| provide/inject | Context |
| Pinia | Zustand / Redux Toolkit |
| Vue Router | React Router |
| Nuxt | Next |
| Teleport | Portal |
| KeepAlive | нет прямого аналога |
| template refs | `useRef` |
| `defineExpose` | `useImperativeHandle` |
| SFC `.vue` | `.tsx` (+ CSS modules/styled) |

Как пользоваться: на любом вопросе «что такое X во Vue?» → «это как Y в React, с отличием Z».

---

#### React — для якоря в голове

Таблица — твой главный мост. Отличия важнее совпадений: мутабельность, template unwrap, emit vs callback.

---

#### Фраза «на автомате» (1–2 предложения)

> Отвечай через мост: Vue X ≈ React Y + отличие (мутации / emit / unwrap).

---

### Q63. Когда выберешь Vue, когда React?

**Короткий ответ на собесесе:**  
Команда, найм, экосистема продукта важнее религии. Vue — быстрый предсказуемый DX на CRUD/admin/средних продуктах. React — больше либ, RN, крупные экосистемы, RSC. На работе следую конвенциям команды.

---

#### Подробно

**Vue уместен:** дизайн-система на SFC, много форм/admin, команда уже на Vue/Nuxt, нужен «официальный путь».  
**React уместен:** мобильный RN, найм/рынок, сложный кастомный рендеринг, уже существующий React monorepo.

Честный senior-тон: «я пишу на обоих; критерий — люди и продукт, не хайп».

Не говори «Vue проще для джунов» — звучит снисходительно; лучше «ниже ceremony для типовых UI».

---

#### React — для якоря в голове

Твой опыт React — аргумент «быстро въеду в Vue-кодовую базу», не «буду всё переписывать на React».

---

#### Фраза «на автомате» (1–2 предложения)

> Выбор = команда/продукт; Vue силён DX и batteries, React — экосистема/RN/RSC; на проекте — конвенции команды.

---

### Q64. Virtual DOM и в Vue, и в React — зачем тогда Proxy?

**Короткий ответ на собесесе:**  
Оба используют VDOM, но стратегии разные: Vue через Proxy знает **какие** данные изменились и где обновлять; компилятор template добавляет patch flags. React по умолчанию идёт от компонента вниз (с ручной мемоизацией).

---

#### Подробно

Vue pipeline (упрощённо):
1. Изменил `ref` → trigger подписчиков.
2. Компонент-подписчик помечается dirty.
3. Scheduler батчит → render → VDOM diff с подсказками компилятора.

React pipeline:
1. `setState` → schedule render функции компонента.
2. Сравнение нового дерева с предыдущим.
3. Memo/Pure/compiler уменьшают работу вручную или автоматически.

Proxy не «вместо» VDOM, а «чтобы знать, кого будить».

---

#### React — для якоря в голове

Signals/Solid часто без VDOM. React Compiler двигает React ближе к авто-оптимизации. Vue давно в «тонкой» зависимости через reactivity.

---

#### Фраза «на автомате» (1–2 предложения)

> Proxy во Vue — точный track зависимостей; VDOM всё равно патчит DOM. React чаще рендерит шире и режет memo.

---

### Q65. Сигналы (Solid/Angular/React compiler) vs Vue?

**Короткий ответ на собесесе:**  
`ref`/`computed` Vue — по сути сигнал-подобная модель уже давно. Solid тоньше (без VDOM). React идёт к compiler/auto-memo. На собесесе: тренд понимаю, Vue уже в этой парадигме.

---

#### Подробно

Сигнал = ячейка значения + список подписчиков.  
Vue: `ref` + dependency tracking в render/computed/watch.  
Solid: сигналы обновляют DOM-точечно без VDOM.  
Angular signals — явный курс туда.  
React — historically push-down render; compiler уменьшает ручной memo.

Не надо говорить «Vue изобрел сигналы раньше всех» пафосно — достаточно точности модели.

---

#### React — для якоря в голове

Твой опыт с `useMemo`/`useEffect` deps = ручной аналог того, что Vue/Solid трекают сами.

---

#### Фраза «на автомате» (1–2 предложения)

> Vue ref/computed ≈ signals; Solid без VDOM тоньше; React догоняет compiler’ом — модель Vue уже dependency-based.
